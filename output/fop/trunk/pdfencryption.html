The Apache FOP™ Project

Apache FOP™: PDF signing and encryption.

Overview

Apache FOP™ can digitally sign and encrypt PDF output. Encryption support was originally contributed by Patrick C. Lankswert and others.

Encryption is commonly used to prevent unauthorized viewing, printing, editing, copying text from the document and doing annotations. It is also possible to ask the user for a password in order to view the contents. Note that the permissions are only enforced by well-behaved PDF viewers: there are third party applications which can remove the restrictions without effort, therefore the degree of protection is limited.

For further information about features and restrictions regarding PDF encryption, see ISO 32000-1 (PDF 1.7) and ISO 32000-2 (PDF 2.0).

Signing

Signing requires BouncyCastle on the classpath. Add these to your classpath or Maven pom file:

<dependency>
  <groupId>org.bouncycastle</groupId>
  <artifactId>bcpkix-jdk15to18</artifactId>
  <version>1.86</version>
</dependency>
<dependency>
  <groupId>org.bouncycastle</groupId>
  <artifactId>bcprov-jdk15to18</artifactId>
  <version>1.86</version>
</dependency>

To sign a PDF you need a PKCS#12 keystore. One can be generated with the openssl command line tool:

openssl req -new -newkey rsa:4096 -nodes -keyout my.key -out my.csr
openssl x509 -req -sha256 -days 365 -in my.csr -signkey my.key -out my.pem
cat my.key my.pem > my2.pem
openssl pkcs12 -export -in my2.pem -out mykeystore.pkcs12 -name myAlias

Then add a sign-params element to the PDF renderer section of the configuration file:

<renderer mime="application/pdf">
  <sign-params>
    <keystore>path/mykeystore.pkcs12</keystore>
    <name>your name</name>
    <!-- Below are optional -->
    <location>London UK</location>
    <reason>text</reason>
    <password>pkcs12 password</password>
  </sign-params>
</renderer>
Element Description Required
keystore Path to the PKCS#12 keystore file Yes
name Name of the signer Yes
location Location of signing No
reason Reason for signing No
password Password of the keystore No

Encryption

Passwords and permissions

The owner password is used to encrypt the document. Many tools for PDF processing ask for this password to disregard any restriction imposed on the PDF document. If no owner password has been supplied but FOP was asked to apply some restrictions, a random password is used. In this case it is impossible to disregard the restrictions in PDF processing tools.

A user password will cause the PDF display software to ask the reader for this password in order to view the contents of the document. If no user password is supplied, viewing the content is not restricted.

All permissions are granted by default. Each restriction removes one permission:

Configuration / command line Restriction
noprint disable printing
nocopy disable copy/paste of content
noedit disable editing in Adobe Acrobat
noannotations disable editing of annotations
nofillinforms disable filling in forms
noaccesscontent disable text and graphics extraction for accessibility purposes
noassembledoc disable assembling documents
noprinthq disable high quality printing

The password length is restricted to a maximum of 32 bytes if the encryption length is 128 or less, and to a maximum of 127 bytes if the encryption length is 256 (longer passwords will be truncated to the maximum allowed).

Encryption length and algorithm

The encryption length determines the algorithm used:

Encryption length Algorithm
40 to 128 (multiple of 8) RC4 (revision 2 or 3)
256 AES-256 (revision 5 or 6)

The default is 128. RC4 is considered insecure and is deprecated in PDF 2.0, so an encryption length of 256 is recommended. Other values are adjusted to the nearest supported value and a warning is issued.

With AES-256, revision 5 (Adobe Supplement to ISO 32000, Extension Level 3) is used by default and the PDF version is set to 1.7. If the PDF version is set to 2.0 (for example <version>2.0</version> in the PDF renderer configuration), revision 6 as defined in ISO 32000-2 (PDF 2.0) is used instead.

Configuration file

Add an encryption-params element to the PDF renderer section of the configuration file:

<renderer mime="application/pdf">
  <encryption-params>
    <user-password>testuserpass</user-password>
    <owner-password>testownerpass</owner-password>
    <noprint/>
    <nocopy/>
    <noedit/>
    <noannotations/>
    <encryption-length>256</encryption-length>
    <encrypt-metadata>false</encrypt-metadata>
  </encryption-params>
</renderer>
Element Description Default
user-password The user password
owner-password The owner password
noprint, nocopy, ... The restrictions to apply (empty elements)
encryption-length The encryption length in bits 128
encrypt-metadata Whether to encrypt the Metadata stream (true or false) true

Command line

Encryption is enabled by supplying any of the encryption related options:

Option Description
-o [password] set the owner password
-u [password] set the user password
-noprint, -nocopy, ... apply a restriction

The encryption length and metadata encryption cannot be set on the command line; use the configuration file for these.

Embedded

When FOP is embedded in another Java application, pass a PDFEncryptionParams object as the encryption-params renderer option:

import org.apache.fop.pdf.PDFEncryptionParams;

[..]

FOUserAgent userAgent = fopFactory.newFOUserAgent();
PDFEncryptionParams params = new PDFEncryptionParams();
params.setOwnerPassword("password");
params.setAllowPrint(false);
params.setAllowCopyContent(false);
params.setEncryptionLengthInBits(256);
userAgent.getRendererOptions().put("encryption-params", params);
Fop fop = fopFactory.newFop(MimeConstants.MIME_PDF, userAgent);
[..]

PDFEncryptionParams provides these setters: setUserPassword, setOwnerPassword, setAllowPrint, setAllowCopyContent, setAllowEditContent, setAllowEditAnnotations, setAllowFillInForms, setAllowAccessContent, setAllowAssembleDocument, setAllowPrintHq, setEncryptMetadata and setEncryptionLengthInBits. There is also a constructor PDFEncryptionParams(userPassword, ownerPassword, allowPrint, allowCopyContent, allowEditContent, allowEditAnnotations, encryptMetadata).

Alternatively, you can set the passwords and restrictions separately in the Map provided by FOUserAgent.getRendererOptions() using the following keys. These are applied on top of encryption-params if both are present, and encryption is enabled as soon as one of them is set.

Key Value
user-password String
owner-password String
noprint, nocopy, noedit, noannotations, nofillinforms, noaccesscontent, noassembledoc, noprinthq Boolean or "true"/"false"

Environment

The PDF encryption implemented in FOP does not need external libraries. Java 1.8 or later is sufficient. Encryption using keys with 256 bits requires unlimited strength cryptography, which is enabled by default since Java 8u161. On older Java 8 updates, the JCE Unlimited Strength Jurisdiction Policy files from Oracle must be installed, or the crypto.policy security property set to unlimited.
